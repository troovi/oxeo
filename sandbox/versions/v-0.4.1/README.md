Снимок библиотеки на момент перед новым API чтения: копия `v-next`, у которой пакеты закреплены номерами из npm. Пример

## Как закреплены пакеты

Имена пакетов совпадают с локальными, поэтому в workspace npm связывает их с папками репозитория, даже если версия
указана ссылкой на tarball. Пакеты снимка лежат в своём проекте `pinned/` вне workspace, а `lib/` импортирует их
относительным путём. Правило версии это держит: `core`, `server` и `client` берут библиотеку только из `lib/`.

Установка — один раз после `npm install` в корне: `npm run pinned -w=@oxeo/sandbox`. Peer-зависимости проект не ставит
(`--legacy-peer-deps`): `react` и `zod` приходят из корня, иначе в приложении оказалось бы два React.

Vite тоже держит один экземпляр на имя пакета, поэтому `@oxeo/client` и `@oxeo/react` исключены из предсборки
(`app/vite.config.ts`): каждая версия разрешает свои копии от своего файла.
